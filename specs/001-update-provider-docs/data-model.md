# Data Model: Update Provider Documentation

**Feature**: 001-update-provider-docs
**Date**: 2026-04-03

This feature has no persistent data model — it modifies source code and generated
markdown files. This document describes the structural entities involved and their
validation rules.

---

## Entity 1: Schema Attribute Description

A `Description` string field added to every `schema.Schema` struct in every resource
and data source file.

**Fields**:
- `Description string` — plain English, ≤ 200 characters preferred, no trailing period required.

**Validation rules**:
- MUST NOT be empty.
- MUST NOT repeat the field name verbatim as the entire description ("friendly_name is the friendly name").
- MUST state whether the value is Computed (set by Twilio) or configurable.
- MUST list all valid values if the attribute is enum-constrained.
- MUST mention `ForceNew` behaviour if applicable ("Changing this forces a new resource to be created.").
- MUST NOT include implementation details (API endpoint paths, SDK method names).

**State transitions**: N/A — static string in source code.

---

## Entity 2: Documentation File

A markdown file in `docs/resources/<name>.md` or `docs/data-sources/<name>.md`.

**Fields**:
- `page_title` — frontmatter: resource or data source type name.
- `subcategory` — frontmatter: Twilio service name (e.g. "Studio", "Messaging").
- `description` — frontmatter: one-line summary.
- Argument Reference section — generated from `schema.Schema.Description` for non-Computed fields.
- Attributes Reference section — generated from `schema.Schema.Description` for Computed fields.
- Timeouts section — generated from `schema.ResourceTimeout`.
- Import section — generated from `schema.ResourceImporter`.

**Validation rules**:
- File MUST be generated by `go generate ./...`, not edited manually (except subcategory
  and description frontmatter, which may be set via template files).
- `make terrafmt-docs` MUST produce no diff after generation.

---

## Entity 3: Generation Tool Configuration

The `//go:generate` directive and `tools.go` file that wire up `tfplugindocs`.

**Files**:
- `main.go` — receives `//go:generate go run github.com/hashicorp/terraform-plugin-docs/cmd/tfplugindocs generate --provider-name twilio`
- `tools.go` (new) — blank import of tfplugindocs under `//go:build tools` build tag.
- `go.mod` / `go.sum` — updated with tfplugindocs dependency.
- `vendor/` — updated with tfplugindocs and transitive dependencies.

**Validation rules**:
- `go generate ./...` MUST complete without error.
- `go build ./...` MUST still succeed (tools.go excluded from normal build by build tag).

---

## Entity 4: CI Doc-Currency Check

A new step in `.github/workflows/terraform_provider.yml` that fails if generated docs
differ from committed docs.

**Step**:
```yaml
- name: Check documentation is up to date
  run: |
    go generate ./...
    git diff --exit-code docs/ || (echo "Run 'go generate ./...' and commit docs/ changes" && exit 1)
```

**Validation rules**:
- Step MUST run after `make build` (provider binary required by tfplugindocs).
- Step MUST appear before `make test` so failures are surfaced early.
- `paths` trigger in the workflow MUST include `docs/**` and `examples/**` so doc-only
  PRs also run the check.
