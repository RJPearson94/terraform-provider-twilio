## Commands

**Setup:**
```bash
make tools       # Install dev dependencies (goimports, tfproviderlint, terrafmt, misspell)
make download    # go mod vendor
```

**Build:**
```bash
make build       # Compile and install provider to $GOPATH/bin
```

**Format / Lint:**
```bash
make fmt             # goimports + gofmt -s on Go files
make terraform-fmt   # Format Terraform example files
make terrafmt        # Format Terraform HCL in acceptance test files
```

**Tests:**
```bash
make test     # Unit tests (30s timeout, 4 parallel workers)
make testacc  # Acceptance tests against live Twilio (60 min timeout, sequential)
```

**Run a single unit test:**
```bash
go test -timeout=30s ./twilio/internal/services/<service>/tests -run <TestName> -v
```

**Run a single acceptance test** (requires live Twilio credentials):
```bash
TF_ACC=1 go test -timeout=60m ./twilio/internal/services/<service>/tests -run <TestName> -v
```

Acceptance tests require these environment variables (validated by `twilio/internal/acceptance/checks.go`):
- `TWILIO_ACCOUNT_SID` — required for all tests
- Per-service vars such as `TWILIO_PHONE_NUMBER_SID`, `TWILIO_FLEX_CHANNEL_SERVICE_SID`, `TWILIO_PUBLIC_KEY`, and address fields (`TWILIO_ADDRESS_STREET`, `TWILIO_ADDRESS_CITY`, etc.)

Acceptance tests provision real Twilio resources and incur cost.

## Architecture

The provider is a standard Terraform SDK v2 provider built on top of `github.com/RJPearson94/twilio-sdk-go`.

### Registration

Each Twilio product lives under `twilio/internal/services/<service>/` and implements the `ServiceRegistration` interface (`twilio/common/service_registration.go`):

```go
Name() string
SupportedDataSources() map[string]*schema.Resource
SupportedResources() map[string]*schema.Resource
```

All services are registered in `twilio/services.go`. The provider (`twilio/provider.go`) iterates that list at startup to populate its resource/data source maps.

### Per-service layout

```
twilio/internal/services/<service>/
├── registration.go              # Implements ServiceRegistration
├── resource_<name>.go           # Resource CRUD
├── data_source_<name>.go        # Data source Read
└── tests/
    ├── resource_<name>_test.go
    └── data_source_<name>_test.go
```

### Resource pattern

- Schema returned by a factory function (e.g. `resourceStudioFlow() *schema.Resource`).
- All CRUD callbacks use `context.Context` and return `diag.Diagnostics`.
- Client accessed via `meta.(*common.TwilioClient).<Service>`.
- Default timeouts: Create/Update/Delete 10 min, Read 5 min.
- 404 detection: `utils.IsNotFoundError(err)` → set `d.SetId("")` and return.
- Optional string fields: `utils.OptionalString(d, "field")`.
- Timestamps stored as `time.RFC3339`.

### JSON fields

Use `structure.SuppressJsonDiff` for diff suppression and `structure.NormalizeJsonString()` / `structure.FlattenJsonToString()` for reading and writing JSON schema fields.

### Validation

SID validators are in `twilio/utils/validation.go`. Each Twilio resource type has a dedicated validator (e.g. `AccountSidValidation()`, `StudioFlowSidValidation()`). Pattern: `validation.StringMatch(regexp.MustCompile("^[A-Z]{2}[0-9a-fA-F]{32}$"), "")`.

### Acceptance tests

```go
func TestAccTwilioXxx_basic(t *testing.T) {
    resource.ParallelTest(t, resource.TestCase{
        PreCheck:          func() { acceptance.PreCheck(t) },
        ProviderFactories: acceptance.TestAccProviderFactories,
        CheckDestroy:      testAccCheckTwilioXxxDestroy,
        Steps: []resource.TestStep{...},
    })
}
```

Import tests use regex against the import ID (e.g. `/Flows/(.*)`).

### Provider configuration

Configured via environment variables or HCL attributes:

| Env var | Purpose |
|---|---|
| `TWILIO_ACCOUNT_SID` | Account SID (required) |
| `TWILIO_AUTH_TOKEN` | Auth token |
| `TWILIO_API_KEY` / `TWILIO_API_SECRET` | API key auth (alternative to token) |
| `TWILIO_SKIP_CREDENTIAL_VALIDATION` | Skip validation on init |
| `TWILIO_RETRY_ATTEMPTS` | Default 3 |
| `TWILIO_BACKOFF_INTERVAL_IN_MS` | Default 5000 |
| `TWILIO_EDGE` / `TWILIO_REGION` | Edge/region routing |
